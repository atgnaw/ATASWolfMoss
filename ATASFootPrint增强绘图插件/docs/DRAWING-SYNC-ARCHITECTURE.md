# Drawing Sync 1.0.0 开发说明

## 层次与扩展点

源码目录保留 `src/DrawingSyncProbe`，程序集和公开指标类身份保持兼容。

| 模块 | 职责 |
| --- | --- |
| `DrawingSyncIndicator` | ATAS 设置、状态显示、图表生命周期、带代次校验的 GUI 调度 |
| `SyncHub` / `ISyncBridge` | 分组、成员心跳、重连、跨组冲突保护、按组限频、代表图选择 |
| `SyncEngine` | 与原生 API 无关的两侧配对状态机，生成变更计划、持久化与应用顺序 |
| `DrawingAdapters` / `DrawingAdapter` | 精确原生类型注册、元数据校验、时间锚点就绪检查、不可变状态读写 |
| `NativeBridge` | 原生存储和对象生命周期、版本保护、ID 索引、批量回读验证；保留已验证的水平线/矩形编解码函数 |
| `PairJournal` | 作用域锁、JSON 原子替换、持久化配对；路径和旧字段默认值兼容 |

添加类型时，在 `DrawingKind` 末尾追加数值（已有 0/1/2/3 不可重排），定义不可变 `DrawingState` record，添加一个 `DrawingAdapter` 子类并在 `DrawingAdapters` 注册。实现元数据验证、`HasAnchors`、`Read`、`Write`，必要时实现 `Prepare` 清除绘制中标记。状态只含值，禁止缓存原生字体、画笔等可变对象。注册表按精确类型匹配，禁止用宽泛 `is HLine` 或基类匹配吸收未经测试的工具。

现有引擎和 Hub 对四类状态没有分支；新增类型通常不需要修改配对算法。原生时间字段代替源图 K 线索引；实现应确认目标图的原生渲染会根据目标周期重算位置。两点对象还需拦截绘制第二个点的中间状态。

新类型至少覆盖：真实原生类型元数据与属性往返、构造器存在、双向新增和修改、缺失锚点/未完成过滤、重连缺侧修复、Global 取消、删除/撤销、混合类型不互相覆盖、跨周期锚点传递、没有变化时零写入。原生 GUI 构造与渲染仍单独做实机验收。

## 单轮流程与性能

1. 每实例 300 ms 心跳请求图表 GUI 回调，待处理回调不叠加；设置变更使用 revision 防止旧回调覆盖新任务状态。
2. Hub 更新心跳、检查成员/身份/线程/组冲突。稳定组仅在 `NextDue` 到期时执行绘图读取，成员变更立即重建基线。
3. 对原生 `SharesInstrumentSnapshot=true` 的桥，每合约侧只选一张代表图读取。其他桥默认合并各图快照，方便测试及未来不同存储实现。
4. 本轮 `NativeReadScope` 共享全局存储读取，退出即清除。快照保留不可读对象 ID，以及整个原生存储的本地 ID，避免把看不见的本地对象当成删除。
5. 引擎比较状态，形成整批 Edit；原生状态相等则跳过写入。新增容量一次计数，不逐个重新统计列表。
6. 有新增或旧配对升级时，一次写入 write-ahead 映射。先保留将解除的旧配对，再执行原生操作。
7. 桥使用本轮建立的 ID 字典定位目标；不为每个 Edit 重扫全体原生对象。每个被修改侧回读一次，验证批内所有修改，然后发一次状态通知。
8. 删除通过回读后再提交移除映射的最终记录；有新增且同时删除时至多两次文件写入。任何持久化/写入/回读异常都会锁住当前会话，不再继续使用已经推进的内存基线。
9. 只有发生变更才请求各图刷新。状态文案变化也会由指标请求刷新；稳定状态不会重复请求。

稳定扫描和批量处理的引擎时间/空间复杂度随对象/配对数线性增长。解除配对批次使用集合标记后统一移除，避免逐条搬移列表。成员分组与心跳仍有小量随图表数增长的工作；原生 API 本身的事件、保存和 UI 渲染成本不由插件控制。不要把纯引擎 benchmark 当成整个平台耗时。

## 恢复与兼容

保留 `WolfMoss.DrawingSyncProbe.dll`、`WolfMoss.ATAS.DrawingSync.DrawingSyncIndicator`、旧配对文件根目录、scope 算法与 JSON 版本。新增种类用追加枚举值保存，旧记录缺 Kind 时仍视为水平线。批量中断可能留下新旧映射并存的 write-ahead 文件，加载容量允许该临时状态，下一轮重新观察原生对象后收敛。

删除映射只能发生在删除确认为成功之后。对于途中失败的创建，已持久化的 ID 可在重连时复用；对于途中失败的取消 Global，旧映射保留，重试清理镜像。ATAS 原生绘图持久化由平台负责，因此插件的写前记录不等同于平台整体事务或磁盘崩溃完全原子性。

全局可见范围不是组范围：同族多个完整组会互相看到镜像，必须阻止并行运行。跨月份、数据源和线程的限制不能仅靠把组名改成唯一名称绕过。

## 验证命令

```powershell
dotnet build .\DrawingSync.slnx -c Release --nologo -m:1 -p:UseSharedCompilation=false
dotnet run --project .\tests\DrawingSyncProbe.Tests -c Release --no-build
.\tools\Build-DrawingSync.ps1
```

测试只在进程内实例化当前安装的 ATAS 原生对象和隔离存储；不会注入运行中的 ATAS。`ReleaseTests.cs` 包含 20 图调度的读写计数、100/1000/2000 个稳定混合配对基准、批量提交及回读故障恢复检查。计时没有固定通过阈值，避免机器负载使测试不稳定；写入次数、读取次数、映射顺序和数据结果是确定性断言。
