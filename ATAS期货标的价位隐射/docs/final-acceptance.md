## 构建与部署

在已安装官方 TWS API 10.45 源码、ATAS 开发引用与 .NET SDK 的开发电脑执行：

```powershell
./tools/Test-IbApiSource.ps1
dotnet build FuturesReferencePriceAxis.sln -c Release
dotnet run --project tests/FuturesReferencePriceAxis.Tests -c Release --no-build
```

当前 Release 为零编译警告、零错误，92 组测试通过。部署文件只有：

- 普通版 1.1.0：`src/FuturesReferencePriceAxis/bin/Release/FuturesReferencePriceAxis.dll`
- Pro 2.2.0：`src/FuturesReferencePriceAxis.DealerHeatmap/bin/Release/FuturesReferencePriceAxis.DealerHeatmap.dll`

两者可以同时安装。Pro 自带所需 SDK 资源，不需要手动复制 CSharpAPI、Protobuf、
共享业务 DLL 或 ReuseProbe 测试程序集。使用电脑仍需能连接已登录且开放 Socket API 的 Gateway。
依赖源码安装是构建前提，不是每台使用电脑都需安装的步骤。

请把旧版 DLL 备份在 ATAS 指标扫描目录之外，完全退出 ATAS 后替换 Pro，再重新启动。
不要通过改名把两个不同构建的 Pro 一起放进扫描目录：它们的程序集和指标身份相同。
版本号保持 2.2.0，区分本轮构建请使用报告中的 MVID／SHA256，而非只看版本号。

## 数据语义快速检查

| 显示 | 含义与注意事项 |
| --- | --- |
| OI DAILY | 当前确认周期取得的日 OI；接收时间不是清算所发布日期。纽约开盘日 08:30 后重确认旧值，不按分钟刷新 |
| Fixed | 上一个完成桶；允许迟到基线，但只显示可确认部分，不推算缺失成交 |
| Rolling | 最近 N 分钟；ATM／接收范围锁定 N 分钟；移出价位停止接收但已有数据自然过期 |
| `?` | 缺少可用数据或基线；不是零 |
| `·` | 当前统计区间没有可用成交事件；不等于证明交易所没有成交 |
| `*`／PARTIAL | 部分覆盖，不是完整时间段累计 |
| RETAINED | 已移出接收范围、仍在滚动窗口中的旧行；不额外保留行情线 |
| FROZEN | 旧有效快照保留供参考，不能误认为数据仍在推进 |

## 如何比较性能

先使用已保留的旧 DLL，再换本版，保持同一电脑、相同图表数量／品种／档数／桶模式／区间／诊断模式。
每轮预热后记录至少 10–15 分钟，并比较成交活跃程度相近的时段；周末空闲不能替代开盘负载。
正式长期稳定性至少需一整个交易日，当前未完成。

- `PerformanceDiagnosticsMode = Summary`：观察 PERF 绘制、快照发布、回调平均值与 P95、事件速率。
- `Record`：另外记录性能汇总，目录为 `%LOCALAPPDATA%\WolfMoss\FuturesReferencePriceAxis\diagnostics`。
  这是诊断文件，不是行情历史数据库。隐藏状态面板不会自动关闭 Record。
- 同时记录共享发送／取消速率、行情线、消费者、连接替换、样本／OI 数量与受监测循环数。
- 对比 CPU／内存走势与卡顿；ATAS 进程数值包含其他指标、图表和连接，不是本插件独占开销。
- PERF 的 P95 是固定直方图区间上界，不是逐样本精确分位数。
- 当前“队列／行情缺口 N/A”仍表示业务接收采用同步回调、没有对应测量；不能解释成零积压或零漏样。
  新历史记录队列是另一条默认未开启的旁路，不会把这个 N/A 变成有效测量。

离线发布基准只用于同一测试口径的回归比较，不代表帧率、整机 CPU 或完整端到端延迟。
保留上升的数值和异常场景，不能只挑下降的结果。详情与原始 CSV 在各阶段报告中。
