## 已修改的行为

### 1. 后台异常必须有人接收

原实现正常释放 Gateway 时，会把连接等待信号设置为“IB Gateway 已释放”异常。
如果先前的等待已经取消或超时，信号及部分后台任务的失败可能没有接收方，
最终通过垃圾回收触发 ATAS 的未观察任务异常提示。

现在正常释放将未完成的连接、合约发现等待置为取消，而不是人为制造连接故障。
连接等待同时响应调用方取消、10 秒超时和 Gateway 生命周期取消；正常释放不会误报 CONNECT_TIMEOUT。

新共享工具 `IbTaskOwnership` 在创建任务时观察最终故障，覆盖连接初始化、reader、
释放、请求完成信号、发送队列、可取消的 WhenAll、共享发现和 Pro 后台调度／释放路径。
`ObserveSend` 不再使用 async void。清理遇到 reader／发送循环异常仍尝试释放本地资源，
真实异常继续向显式等待者传播；失败发送仍按已有策略淘汰连接。

没有安装全局 UnobservedTaskException 处理器，也没有屏蔽 ATAS 或其他插件的异常。
强制 GC 的测试事件监听只存在于测试工程。

### 2. Pro 外部数据只使用统一实时 UTC

Nightwatch 调度、IB 目标日期／订阅窗口、OI 重试和 Flow 发布改用系统 UTC 的 TimeProvider。
ATAS UtcTime 仅在新增诊断中作为对照，不再为这些 Pro 实时功能选择时间桶。
普通版及共享映射轴原有时钟行为没有变化；不新增历史回放支持。

IB 源时间仍使用 API 原始时间戳；接收时间仍为收到回调时的系统 UTC。
没有用接收时间覆盖源时间，没有给原始事件平移几分钟。

Flow 发布将墙钟变化与单调计时器比较：两者偏差超过 2 秒时视为校时事件。
正常的循环变慢或暂停，如果两种计时同步推进，不会误判为校时。
发生校时时清除固定／滚动累计基线、重建观察区段，丢弃可能来自未来的已发布帧；
之后重新积累，不能跨时钟跳变相减。短暂等待或部分覆盖属于安全重建的预期结果。
固定桶缓存现在要求桶结束时间精确匹配，不会沿用结束时间更晚的“未来快照”。

该修复消除了代码中混用时钟的路径，但还没有实盘证据证明之前所有交替空白都由它造成。
系统时间本身仍需准确；插件不会擅自修改 Windows 时钟。

### 3. 可以直接核对输入、选桶和错误来源

仍通过 `Performance diagnostics` 设置使用：

- Off：不采集新增逐样本诊断，不写诊断文件。基本时钟安全保护仍工作。
- Summary：每秒生成 UI 汇总，不创建诊断文件。
- Record：同时保存脱敏 JSON／CSV，目录、写入上限和保留策略沿用原实现。

目录：`%LOCALAPPDATA%\WolfMoss\FuturesReferencePriceAxis\diagnostics`。
Record 记录的是诊断证据，不是完整逐笔行情录制或数据库回补。

新增 UI 行均明确标为 UTC，不受显示时区设置影响，便于直接比较：

| 字段 | 含义 |
| --- | --- |
| CLOCK UTC / ATAS / 偏差 | 系统 UTC、ATAS 报告的 UTC、ATAS 减系统的秒差 |
| 校时 | 检测到的系统墙钟调整次数，并非 ATAS 偏差次数 |
| FLOW 源 / 接收 | 最后一次相关输入的原始源时间与本地接收时间 |
| 接受 / 拒绝 | 当前指标在诊断开启期间、选定成交口径的累计输入计数 |
| 迟到 | 源时间早于当时已发布桶结束、接收时间晚于该结束的输入数量 |
| 拒绝分类 | 未来源时间、观察基线前、执行价范围外、交易区段外、倒序、无效累计值、滚动边界 |
| UTC 桶 / 覆盖始 | 当前快照区间与当前连接观察覆盖起点 |
| 最后错误 | 历史最近错误分类、来源、可用 IB 原始码及发生 UTC，不等于当前仍失败 |

注意：

- “接受”表示输入进入累计样本，不保证这个已完成桶一定能形成差值。
- “迟到”是独立观察计数，可能同时计入接受或拒绝；不代表自动修订已发布桶。
- “源 / 接收”是最近输入对，不是所有合约的新鲜度保证。完整日期见 CSV。
- 滚动边界目前合并报告重复／倒序、非活动范围和观察段边界等滚动拒绝，未逐原因拆分。
- 无效值的两个计数分别为指标累计值拒绝、共享 Gateway 的解析失败；后者为连接级累计。
- 空桶不再只能依靠问号猜测，但这些计数不能证明交易所完全没有成交。
- 当前行队列及完整行情缺口仍显示 N/A，不伪装为零。

LINE_LIMIT 的来源现在可区分：

- LOCAL_BUDGET：插件本地准入预算拒绝，不带伪造的 IB 原始错误码。
- IB + 101：真实 IB 错误回调通过订阅扇出传到指标。

本批没有重做额度分配或自动恢复状态机。其他客户端也可能消耗账户额度，
因此插件的本地预算并不保证账户一定还有相同数量的可用行情线。

CSV 使用 schema_version 2，保留原有前 23 列的位置，追加时钟、区间、接收分类、
错误来源和目标品种／到期日；JSON 增加成交口径。未知值留空。
不记录 API Key、请求头、账号或底层完整异常对象；分类与来源使用白名单。

## 自动化证据及性能边界

新增八组验证：

1. 单调时间与墙钟前跳／后跳、稳定恢复、循环长时间暂停。
2. QQQ／SPX、1／3／5／10 分钟的实际 Pro 发布路径与未来缓存拒绝。
3. 实际固定与滚动发布在校时后重建基线，不生成跨断点权利金。
4. 接收分类、迟到计数、严格零分配计数器和 CSV 脱敏／字段对应。
5. 真实指标接收路径的未来、基线前、范围外、区段外、倒序及无效样本拒绝。
6. 所有共享等待者取消后的迟到失败、重试及显式 await 仍传播异常。
7. 未完成连接正常释放、故障任务实际被 GC 且不触发未观察异常。
8. 假 Socket 走真实 Gateway 的本地预算、IB 101 扇出及非法源时间计数。

原有兼容、普通版隔离、跨插件 SDK／Client ID、固定／滚动、缓存和历史接口测试继续通过。
已有微检查仍为 10,000 次 IB 回调扇出分配 0 字节，100 次固定重复发布分配 22,400 字节。
新增接收计数的 10,000 次循环在预热并隔离 JIT 后严格检查 0 字节。
这不是 ATAS 帧率或实盘 CPU 加速比例；本批也没有运行新的完整性能对比基准。

异常观察在创建后台操作／请求任务时建立，不为每条正常行情创建新任务。
诊断汇总和 CSV 格式化在每秒诊断循环中执行，不在 OnRender 做网络、文件或诊断汇总等待。

## 建议人工验收

1. 自行保留旧 DLL，按原部署流程替换 Pro 并重新加载 ATAS；本次工具未替你部署。
2. 开启 Summary 核对 CLOCK 偏差、FLOW 源／接收／桶结束。桶结束不应超过系统 UTC。
3. 如再次交替空白，开启 Record，保留现象前后数分钟的 JSON／CSV 与截图，
   包含模式、区间、品种、时区、LINE_LIMIT 来源和原始码；不要附 API Key。
4. 重复启用／关闭 OI 与 Flow、移除指标、重新添加，检查是否仍出现未观察任务异常弹窗。
5. 无行情时允许未知、WARMING 或 CLOSED，不能用休市时段确认实盘数据完整性。
6. 不必为了验收主动修改系统时间；跳变场景已通过离线可控时钟测试。
