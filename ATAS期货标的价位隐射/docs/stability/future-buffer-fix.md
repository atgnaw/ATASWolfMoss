# 小幅超前行情暂存修复

日期：2026-09-11；Pro 2.3.0。普通版、系统校时和 Nightwatch 请求调度不变。

## 处理规则

- 在实际使用的共享 Flow 统计组内处理，固定与滚动模式共同适用。
- 源时间不晚于本机接收时间的普通回调，继续原来的处理路径。
- 超前大于 0 且不超过 1 秒，先暂存，不计入“未来拒绝”。
- 超前超过 1 秒，仍按 FutureSource 拒绝，保留最近两端时间及最大拒绝超前值。
- 暂存样本只在实际 UTC 达到其原始源时间后尝试写入；不修改样本时间或原始接收证据。
- 同一合约的后续输入不能先于尚未到时的队首写入；原有倒序、累计值和观察边界检查仍生效。
- 相同配置组的图表共享队列，重复回调不再次计入。其他合约不会被该合约的等待阻塞。
- 没有新回调时，由已有的发布循环处理到时样本，不新建定时任务或增加 IB 请求。

## 安全边界

- 每合约最多暂存 128 条，每组最多 4096 条；最多保留原接收时刻起 3 秒。
- 队列超量或超时：丢弃对应合约的暂存，结束该观察段，待下一次有效配置建立新段，避免跨缺口相减。
- ATM 移出范围、最后一个观察者退出、断线暂停、校时跳变，会清理相应未到时队列。
- 品种、到期日或配置组变化不会将旧队列迁入新组。
- 交易区段外事件不入队；相同交易时段内容的不同图表数组不会误清队列。
- 区段结束后到时的旧区段样本按原事件时间处理，不因处理时间已经收盘而误切入新段。
- 1/3/5/10 分钟桶仍按原有语义运行，固定桶仍保留原有 3 秒发布缓冲。
- 旧的非共享参考/测试聚合路径继续严格验证时间；线上 IB Flow 在共享组内执行本策略。

## 诊断和验收

性能 UI 增加 `FLOW 超前缓冲(共享组)`：待处理、累计暂存、成功补入、丢弃、最大暂存超前毫秒数和本图溢出次数。

这些“共享组”统计不是每图独立统计，不能直接与“本图写入”相加。
`暂存` 不等于写入，也不等于拒绝；只有通过原有校验的样本才增加 `补入`。
排队后因边界、过期或校验失败丢弃的数量显示在 `丢弃`。
原来的最近/最大“未来拒绝”证据与新缓冲证据分开，不会被小幅暂存覆盖。

Record 元数据 schema_version 为 5，原 56 列不变，追加：
`flow_buffered`、`flow_buffer_overflow`、`future_pending`、`future_buffered`、
`future_released`、`future_discarded`、`future_buffer_max_lead_ms`。

完全退出 ATAS 后替换 DLL，开启 Summary 或 Record 及性能信息分类。
当超前仍在约 32–410ms 范围时，应看到“暂存”和“补入”增长，而不是“未来拒绝”增长。
待处理通常很快归零；若持续丢弃或超前大于 1 秒，保留诊断继续查原因，不自动扩大容差。

## 验证结果

- Release：零警告、零错误，130 组离线测试通过。
- 新增 3 组覆盖 1 秒阈值、按源时间分桶、同合约顺序、共享去重、晚到的图表回调、
  1/3/5/10 分钟固定与滚动、跨区段、换档/重入、断线、时钟回退、过期和数量上限。
- 实际指标的双图回调/发布测试确认只暂存并补入一次；原有零分配热路径测试继续通过。
