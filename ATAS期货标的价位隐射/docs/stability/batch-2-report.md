# 稳定性修改第二批：统一品种 ATM 与接收范围

日期：2026-09-09。本报告属于新稳定性计划，不是此前 performance 目录中的第二批。
第二批完成时全量 104 组离线测试通过；随后按授权直接实施第三批。
最终 DLL、全量结果和验收入口见 [第三批报告](batch-3-report.md)。

## 实现

- 每个共享 IB 连接内，按 ticker + expiration 建立一个 ATM 协调器。
- 默认由最先成为有效来源的图表提供映射现价。主图被移除或当前柱回调超过 30 秒未更新时，选择有新鲜报价的后备图表；没有新鲜来源则保持原 ATM，并标记 STALE。
- 报价新鲜度来自 ATAS 当前柱 OnCalculate 回调，不以后台轮询刷新代替，也不宣称为交易所时间戳。重新计算当前柱也可能更新该时间。
- 取当前启用 Flow 消费者的最短 1/3/5/10 分钟周期作为接收范围换档节奏，对齐 IB 实际交易区段起点。新增／删除配置从下一个未来边界应用，未到边界不立即改变 ATM。
- 固定桶、滚动桶共享接收节奏，不互相锁定；各自统计周期由第三批的设置组维护。
- 同品种需求按最大请求档数计算，再服从插件预算；小档数图表取统一范围的中心子集。多品种继续公平、对称缩减。
- 换档先取消所有图表的旧边缘合约，再允许新增边缘；范围围栏拒绝落后图表重新打开已退出合约。异步合约发现过期时重新同步，不因 RANGE_CHANGED 反复销毁连接。
- 普通版未修改，未增加外置业务依赖 DLL。

## 离线证据

新增四组测试：混合周期与过期版本、主图失效接替及品种／日期隔离、共享最大档数与预算、真实订阅客户端的边缘围栏及释放。
最后一组使用模拟 Socket 驱动生产客户端，不连接 Gateway，验证两个消费者换档仍保持 42 条预算，落后消费者不能重订旧边缘。

PERF 新增 `ATM 统一` 行：ticker、主图编号、STALE、换档周期、下次 UTC、接收档数和实例数。
这些协调信息目前是 UI 摘要；不要将主图编号当成 IB Client ID。

## 人工验收

1. 两张 QQQ 图表使用同一 Gateway host/port/client_id，分别设 1m 与 5m；检查 ATM 统一行都显示 1m。
2. 故意让图表报价短暂不同，检查它们不会各自扩展成不同接收范围；暂停主图后检查 STALE／后备接替。
3. 改为 3m 与 5m，检查下一个共同未来边界采用 3m，5m 统计仍为 5m。
4. 删除最短周期消费者，检查协调周期随剩余配置变化；QQQ + SPX 21 档情况下插件预算仍为最多 84 条长期 Flow 行情线。

插件预算不是整个 IB 账户额度；Gateway/TWS 或其他客户端的占用仍可能导致真实 IB LINE_LIMIT。
本批没有实盘性能改善百分比，也未处理 OI 全零的上游数据质量策略或所有 OI 开关生命周期问题。
