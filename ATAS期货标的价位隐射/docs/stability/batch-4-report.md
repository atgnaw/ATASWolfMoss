# 稳定性第四批：OI 生命周期、质量提示与订阅恢复

2026-09-10。按本轮授权连续完成第四、第五批；本报告对应新的稳定性计划，非旧 performance 目录的第四批。

## 本批变更

### OI 开关不再重启 Flow

Flow 开启时，OI 显示开关只改变 OI 展示与快照失效标记，不取消 Flow 调度、不清空样本、不释放共享统计组，也不重新建立连接。
Flow 的既有行情线固定包含 generic tick 101；OI 开关不再通过增删 101 导致整条 reqMktData 被取消重订。
这不增加期权行情线，也不新增 OI 分钟轮询。Flow 关闭、只运行 OI 时仍使用既有临时订阅策略；两列都关闭仍释放连接所有权。

同一指标的普通样式更新不分裂统计组；连接、品种、到期日、周期或成交口径等实际数据配置变化仍走正常重配置。

### OI 全零与故障边界

- 所有已解析可见合约都收到 0 时，保留真实零值，提示“全部为 0，请核对上游日 OI（非缺失值）”。有非零更新时提示自动消失。
- 未返回数据仍与 0 严格区分；不把全零认定为 API 错误，不伪造上一日非零数据，不增加高频复核请求。
- 日 OI 的确认周期与原子本地缓存机制不变；本批没有手动改动用户已有 OI 缓存。
- 按合约保存订阅错误，防止定时发布马上将权限／行情线错误覆盖为 LIVE；已有健康行继续显示，部分错误显示 PARTIAL。
- 已确认的 DAILY OI 不因 Flow 实时订阅错误被改为无效。缺失 OI 的订阅错误保持可见，真实数据返回后清除对应错误。
- 延迟行情按当前合约集合维护，正常实时更新可解除 DELAYED，不再使用永远无法清零的累计布尔标记。

### 有界恢复

对有具体 request_id 的 IB 100（发送频率限制）和 101（行情线限制），增加客户端内共享的恢复扫描：最多每 5 秒扫描一次，每个保留订阅最多重发 3 次，使用 5/15/60 秒退避，并服从已有有效行情线预算／IB 限额观察窗口。
权限错误不自动反复重发；恢复尝试耗尽后需要实际订阅重建、重新连接或用户调整配置。
这不是自动购买权限、抢占其他客户端，也不保证限额外的行情线一定能恢复。

订阅错误会结束相应合约的旧观察段。恢复后重新建立基线，保留已经确认的旧段数据，但不跨未观察缺口相减。
未知内部错误也清理旧订阅并暂停观察，再替换连接，避免遗留 lease。

补充检查发现：重建 Socket 后，新 ATM 协调器若从版本 1 开始，会被仍保留的共享 Flow 组误认为过期版本。
现改为程序集内单调递增的版本编号，新连接的范围不会倒退；不同插件仍保持各自源码内编译的隔离状态。

## 离线验证

第四批初次全量 120 组通过；最终版本随第五批统一回归。
新增测试覆盖实际 OI 设置反复切换不取消调度／不改变 Flow 快照、全零提示与恢复、按合约错误与延迟解除、临时订阅错误有界重试及权限错误不自动重试。
连接替换版本连续性也已加入原有协调器测试。
