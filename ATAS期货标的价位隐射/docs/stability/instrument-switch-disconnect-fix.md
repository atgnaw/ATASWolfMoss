# 切换品种后 Client ID 占用：连接释放修复

## 原因

官方 TWS API 10.45 的方法是 `eDisconnect(bool resetState = true)`。
原有反射调用用零个参数查找方法，找不到后又被清理辅助方法吞掉异常。
因此在 ATAS 切换品种、重建指标或其他连接释放场景中，旧 Socket 可能没有真正关闭，
而本地 Client ID 预留已经释放，新连接便可能收到 IB 326。
此前 FakeSocket 使用零参数方法，与官方签名不一致，未暴露此错误。

## 修改

- SDK 适配层显式调用 `eDisconnect(true)`，使用精确的 bool 参数签名。
- 初始化完成后再次断开并核对连接状态；最终失败会使释放任务失败，而不是静默成功。
- 最终断开失败时保留本地会话预留；连接池原有失败释放屏障也保留，避免继续重用未释放的 Client ID。
- 模拟 Socket 改为与官方一致的可选 bool 参数。
- IB 326 的诊断来源改为 IB，并记录原始错误码 326，不再误标 LOCAL。

## 用户验收

先完整退出 ATAS，再替换 Pro DLL 并重新打开，以清除旧版本可能遗留的 Socket。
同插件各图表保持相同 host/port/client_id，然后反复切换 NQ → ES → NQ。
检查不再出现 326，合约发现和行情线恢复；OI/Flow 数据是否有值仍取决于数据源和观察区间。
若仍出现冲突，应检查 Gateway 中其他客户端是否实际使用相同 ID，不能自动抢占其他程序连接。
