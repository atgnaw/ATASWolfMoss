# 三日买卖比例与过滤研究

[打开交互报告](research.html)。完整研究数据为 `research.json`。[逐笔审计与补充实验](audit.html) 展示原始成交核对、18种后报价实验和698个过滤候选的跨日表现。

## 当前可执行的候选

分类保持 **233 全部成交＋中间价法＋接收时最新报价＋无年龄上限＋U15开启**。

过滤另算一份 **相同成交口径、相同报价对齐、相同U15开关** 的贴价法结果。两份结果各自计算 `买 / (买 + 卖)`：

```
方法差 = abs(中间价法买方比例 - 贴价法买方比例)
方法差 <= 0.01：保留（相差不超过1个百分点）
方法差 > 0.01：标记为方法敏感，可过滤
任一方法没有买卖可比较量，或总量不一致：不可评价，不补成0分
```

它不修改任何逐笔分类，不使用UW数据做实时判断，也不把过滤后的比例冒充全市场真相。过滤掉的桶仍留在报告里，能查看原因。实现见 `tools/IbOptionFlowProbe/BuySellStability.js`；参数 `maximumGap` 使用0–1的小数，而不是百分数。输入数组顺序为买、卖、中性、未知，必须使用相同的数量或权利金单位。本实验只验证了按张数统计。

这是**下一批数据的待验证候选**，不是准确率承诺；未替换生产采集器或原报告的默认算法。

## 数据范围与主指标

- 9/23，13:30–13:55，100桶。
- 9/28，15:35–15:55，68桶。整个15:55–16:00排除，不只剔除一个数量异常合约。
- 9/29，15:30–15:55，89桶。
- 所有日期均排除UW最后桶、未还原行、IB未完整覆盖的时间段。共257桶，已观察IB 940,246张，UW 939,273张。

主指标是 `abs(IB买/(买+卖) - UW买/(买+卖))`，以**百分点**表达。Mid和未知不参与分母；买卖分类覆盖率同时展示。平均误差以UW桶总张数加权，P95和最大值按桶统计。不可计算比例的桶记缺失，不能算0误差。完整来源路径、窗口、排除统计和输入HTML的SHA256在JSON中。

## 为什么不只提高原评分

同一组样本，要求最新报价辅助评分≥0，只保留146桶和38.95%的IB量，平均误差反而为2.6000点，最大误差仍为84.2749点。

最明显的例子是9/29 15:35–15:40 QQQ 740 Put：UW买995/卖77，IB买92/卖985，买方比例相差84.2749点。原评分为0，最新和条件式结果相同；但中间价与贴价法相差37.9490点，方法差过滤能识别这种敏感性。UW该桶的多腿比例为85%，仅作事后背景，不作为过滤输入，也不能据此断定误差一定由多腿造成。

9/23原异常桶QQQ 738 Call的方法差约1.6025点，能被1点阈值排除；若放宽到2.5点，会重新保留。阈值敏感度可在报告中直接比较，不能只展示最优单点。

## 防止样本内拟合的检查

1. 对全部72组配置做整日留出：用另外两日选配置，三次均选出上面的最新报价基线。训练要求每一天买卖覆盖≥70%、所有桶都可计算比例。
2. 固定306个过滤候选：单因素或限定两因素组合；包含评分、模拟改变比例、大单量、超时、未知、覆盖、样本量、方法/成交口径/年龄敏感度。实时筛选特征不读取UW答案。
3. 过滤训练同时约束每个训练日的桶数和IB量保留率，比较60%、70%、80%、90%四档。目标为按交易日等权的 `加权平均误差 + 0.25*P95 + 0.10*超过10点的桶比例`。
4. 全候选族留出选择并不稳定：60%目标在9/23、9/29选方法差≤1点，但9/28选覆盖≥90%，仍漏掉该日34.13点的大偏差桶。合并留出结果保留182桶，均值1.7354点，最大34.1270点。不能将全样本固定1点过滤的17.2440点最大误差包装成该流程的独立验证成绩。
5. 后续限定为“方法差”这一候选族时，三次留出均选1点；按日期先后重放，9/23选的这一阈值也能用于9/28、9/29。但**候选族本身是在看过三天结果之后重点检查的**，仍有选择偏差。只有新交易日、预先冻结规则的采集才能作真正新增验证。

此外，混合最新报价与条件式结果（条件式权重25%、50%、75%）均未改善总体平均误差。方法差>30点时改用贴价法，样本内均值可从2.0695降到1.9966点，但大偏差桶反而从13增至14、P95也恶化，因此没有直接把这种改分类方法部署为默认。

## 逐笔审计后的最终建议

重新读取三日原始回调及0.9.2逐笔决策：119,358条纳入的233成交回调重算为940,246张；257桶的买、卖、中性、未知数量逐项与比对报告相同。JS补充分类器使用十进制精确比较，并逐笔与原C#决策核对贴价法和中间价法；50毫秒窗口使用UTC小数秒精确相减。该一致性证明重算正确，不证明上游采集完整或方向真实。

### 为什么评分0仍可能有严重错误

9/29 QQQ 740 Put那笔903张，价格1.88，前报价1.85/1.93；Bid年龄6564.1264ms，Ask年龄954.422ms。47.5152ms后第一份后报价1.85/1.88，把成交价判在Ask。但原合并算法仍取1.85/1.93，分类不变，评分0。只对此笔改用后报价会把桶统计从买92/卖985/中性5变成买995/卖82/中性5，接近UW买995/卖77/中性10。

然而，18个统一后报价规则（6档前报价年龄×3种后报价要求）并未给出稳定优势：样本内最好的“前报价≥5秒、前后都能判断买卖时用后报价”将均值2.0695降到2.0075点，但改善集中在9/29，9/28反而由2.3865升到2.4337点。用9/23+9/28训练，仍选原最新报价，在留出的9/29并不会提前选中这项修正。**不据单个903张案例替换默认分类。**

### 四个残余桶不是同一种问题

- 9/23 SPX 7705 Put：409张@4.10，前3.90/4.00，U15判买；首个后报价4.10/4.00交叉，回退前报价。两种分类方法对报价外成交用同一U15规则，所以方法差为0仍有风险。该桶报价外量占28.71%。
- 9/28 QQQ 736 Call：392张@0.64、前0.63/0.64，前报价年龄约254ms；后0.64/0.64锁定，合并仍判买。不是只要排除陈旧报价就能解决；两方法在贴价成交上完全一致。
- 9/29 SPX 7665 Call：两笔55、51张分别由贴Bid在后报价下变为买或中性，说明小于QQQ100张阈值不等于影响很小；SPX按50张进入条件式。但仅有UW桶汇总，不能认定哪笔就是UW的另一类。
- 9/23 SPX 7700 Call：最大190张本来在中间价，另一笔111张原贴Ask；后报价改变区间。报价整体很新（量加权293ms），依靠报价年龄也不足以解释10.18点差异。

### 补充过滤的收益与代价

加入集中度、有效笔数、报价年龄、价差宽度及报价外成交占比等后，共698候选。60%训练保留目标的整日留出结果保留172桶、81.39%的IB量，均值1.8423点、最大17.2440点、大偏差剩3桶。不同留出日选出的第二个条件不同，并未形成稳定的统一补充规则。

三天合并拟合“方法差≤1点且报价外成交量≤15%”，可保留173桶、83.85%的量，均值1.5401点、大偏差剩3桶。这是样本内成绩；为比简单方法差过滤少漏1桶，多损失约8.53个百分点的成交量，且跨日条件不稳定。暂不推荐把这一附加门槛强制开启。

**交付候选保持简单版本：原最新报价分类＋可选方法差≤1点过滤。** 原评分保留作诊断，不把它当准确率。默认不修改原历史报告或生产程序；新研究页能比较阈值、列出所有被过滤桶及原因。剩余4桶明确列出而非强行拟合为0。正式推广前应将此规则冻结，在未参与选择的新日期复核；这不改变本次三日研究已得出的样本范围内结论。
