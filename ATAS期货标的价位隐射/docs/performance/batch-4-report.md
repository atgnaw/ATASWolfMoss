## OI 日确认与时间语义

此前只要 con_id 已存在于内存／日缓存，就一直当作已经取得。
例如周五或周末读到下周一到期合约的 OI，周一可能不再重新确认。

现在按每个合约保留独立接收时间；纽约交易日 08:30 为新的本地确认周期起点：

- 08:30 前以及周末、节假日，沿用最近一个开盘日 08:30 开始的周期。
- 新周期开始后，旧值仍可显示，但不算本周期已确认。
- 全部已有值均待确认时为 FROZEN；新旧或缺失混合时为 PARTIAL；
  完整且本周期确认后为 DAILY。状态文字说明“旧值待确认”数量。
- 缺失／待确认项按原有限快速重试以及 08:30、09:15、09:35 重试；
  当天时点耗尽后，下一次为下一开盘日 08:30，不再永久停在 DateTime.MaxValue。
- 已成功确认的合约不按分钟重取。同日相同值重复推送不会刷新接收时间、反复写盘或重建 OI 画面；
  数值修正仍被接收，乱序的旧 OI 不覆盖新值。
- Flow 同开时共享行情线。OI 完成后移除不再需要的 101 需求；新周期再加入需求，
  通过已有订阅协调器合并，其他消费者仍需 101 时不会移除其需求。
  更改 generic tick 需求可能触发原协调器的一次取消／重订，不增加长期独立 OI 行情线。
- OI 顶部时间仍为最新有效接收时间；悬停显示当前 Call／Put 合约自己的接收时间，
  而不是借用另一合约的更新时刻。故障不再把 OI 的数据时间改成报错时间。

**08:30 是插件的重新确认策略，不是对 IB／清算所发布时间的保证。**
IB tick 27／28 给出 OI 值，但不能据此确定该值对应哪一次清算发布。
即使本周期收到新推送，也只表示“IB 本周期返回的值”，不宣称盘中实时 OI 或最新清算日期。
原字段定义见 [IBKR Tick Types](https://interactivebrokers.github.io/tws-api/tick_types.html)。

## 缓存可靠性与开销

- 新缓存 schema_version=2，逐 con_id 保存 OI 和 received_utc。
- 旧格式仍可读；使用原文件的真实 received_utc，不把迁移或加载时间伪装成数据时间。
- 过期目标不再加载。错误 ticker、未来时间、无效值、未知 schema、损坏 JSON 被忽略；
  零仍是有效 OI，不等同于缺失。
- 单文件读取限制 1 MiB，最多 4096 条；写入超出条数时优先保留接收时间较新的条目。
- 多图表的子集写入按 con_id 合并，较旧接收时间不能覆盖新值。
- 写入采用同路径独占 .lock 文件、唯一临时文件、flush 和原子替换；
  竞争写入快速失败，由后台 30 秒后重试，不阻塞渲染。
  .lock 是持久的锁文件名；真正的锁随文件句柄关闭释放，并非锁文件存在就表示占用。
- 失败保留内存数据及 dirty 标记，并在 OI 状态消息提示本地缓存写入失败。
- 文件读写不持有行情数据锁。停止一代订阅时尝试保存尚未落盘的 OI。
- 未删除用户已有缓存文件；过期文件只是不再用于目标数据。
- OI 逐合约时间元数据单独存于 OI 快照，没有扩大每次 Flow 发布的行结构。

## 目标与 Flow 边界

- ticker／expiration 变化时先释放旧订阅、清空旧目标快照，再查询新合约；
  新合约发现失败时显示新目标等待／错误，不再留下旧目标的价位。
- 旧目标回调（包括错误回调）不更新当前目标。
- 固定桶只允许当前观察范围内、非未来、属于实际开放区段的合约事件进入。
- 计算时不以之前交易区段的累计值作为新段基线；例如午间维护后第一笔较晚，
  使用已确认的部分成交并标记 PARTIAL，不把整段维护缺口计入。
- 断线／订阅代际退出后保留已发布快照，但清除固定累计基线；
  恢复后重新观察。Rolling 继续保留此前已实现的独立观察 run，不跨缺口相减。
- 固定模式乱序事件不再清空有效历史。成交量、累计权利金或乘数重置会重新建立基线。
- 累计／首笔／多 run 合计数值溢出不会生成异常大柱或使整列计算抛出；
  无效单元保持无数据语义。
- 固定模式在非交易区段且没有完成桶时显示 CLOSED／等待下一开放区段，
  不再一直显示“等待第一个完整时间桶”。
- 1／3／5／10 分钟、固定桶及 Rolling 的 ATM 锁定和移出范围保留规则不变。

IB 时段解析补齐同日逗号分段、旧式短端点、带日期端点、2400、跨夜 RTH 交集。
保留维护间隙以及相邻区段各自的桶锚点；真正重叠区段归并。
QQQ 仍按 NYSE 开放日及半日市裁剪 RTH，SPX 保留 IB 返回的 GTH／RTH。
未知／空时区、DST 不存在或有歧义的端点不猜测时区／偏移；
因此异常合约时段可能没有可统计区段，需要核对 IB 返回值。
字段约定见 [IBKR ContractDetails](https://www.interactivebrokers.com/docs/tws-api/ref/contract-details)。

## 用户验收

1. 保留旧 DLL 在 ATAS 自动加载目录之外；同一时间只安装一个 Pro 版本，普通版可并存。
2. 不需要手动删除旧 OI 缓存。核对目标 expiration 与每个 Call／Put 的悬停接收时间。
3. 跨开盘日 08:30 ET 时观察旧值待确认→PARTIAL／DAILY；未回数时保留旧值并明确标记。
4. 测试 OI-only、OI＋Flow、多图表及关闭功能；关注重订数量、实际行情线和缓存失败提示。
5. 开放区段切换、短暂断线后，Flow 可以出现部分覆盖／未知，但不能跨缺口累出大柱；
   固定和 Rolling 的 1／3／5／10 分钟都需要实盘确认。
6. 同配置采集 10–15 分钟 Record，对比第三批／第四批的 Events/s、Publish／Callback／Render，
   把启动、换档、重连与稳定区间分开比较。不能用周末空闲状态证明实盘 CPU 改善。
