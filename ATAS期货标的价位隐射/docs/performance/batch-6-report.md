## 本批实现

新增独立源码模块 `shared/WolfMoss.MarketData`，不引用 ATAS、IB、WPF 或数据库。
IB 的 props 自动导入该模块；其他插件复用时需要同时保留两个相邻源码模块。
它们在各插件内单独编译，不增加需要部署的共享业务 DLL。

提供 `IMarketEventSink`、`IMarketEventBatchWriter` 和 `IHistoricalDataReader`：

- 接收入队立即返回 Accepted／Disabled／Congested／Faulted；Accepted 不代表持久化完成。
- 不可变事件包含来源、种类、schema、运行段和接收序号、合约、来源／接收时间、
  交易时段上下文、成交口径、连接／观察代际和质量标记。
- IB 保存累计成交量、VWAP、乘数、可用成交字段及 OI；零 OI 是有效值。
- Nightwatch 保留桶起点、采样时间、独立复制的执行价节点和 GEX summary。
  GEX 交易日不冒充到期日，未知源时间不冒充接收时间。
- 预留派生结果的算法版本、桶模式／区间、ATM／价格范围和部分覆盖信息，但本批不生产派生历史记录。
- 历史查询按合约／来源／种类／口径及 ReceivedUtc 的半开区间筛选，支持分页、取消及缺口说明。
- 记录模型不含 Key、Key 指纹、请求头、账号或完整底层异常。

接入点在共享接收端：IB 解析后、扇出到各图表之前；Nightwatch 在共享下载成功解析处。
多个图表共用同一来源结果只捕获一次，缓存命中不重复捕获。
实际新请求即便得到相同 as-of，也是一条新的观察，不宣称它是新的交易所采样。
订阅取消／替换、断连、来源不可用等保存为明确的观察边界，不跨未观察段伪造连续性。

生产默认没有 Attach、队列或录制任务；禁用路径不构建逐事件记录对象。
当前设置中没有行情录制开关，性能诊断 Record 与行情记录相互独立。
writer／reader 的内存与慢存储实现只在测试中，未进入 Pro。
完整契约及接入约定见 [历史接口指南](../../shared/WolfMoss.MarketData/README.md)。

## 有界写入与完整性

可选 BufferedMarketEventSink 默认队列 1024、每批 64、空闲检查 100 ms，
只用非等待 TryWrite。存储工作在自己的任务，不在实时回调或 OnRender 执行。
队列满时记拥塞缺口，不增加无界任务／等待集合；禁用时没有这项后台开销。

每个运行段有累计损失账本：拥塞、捕获失败、写入失败、关闭时未确认交付。
正常状态下即使没有新行情，也会尝试将更新的缺口账本写入空批次。
正常释放先排空，默认 2 秒后取消；重复／并发释放不会重复关闭新记录器。
修复了最后一批写入期间新产生缺口时，停机提前退出而未补写账本的边界。

writer 故障后停止该记录器，不自动重试，不阻断实时图表消费者。
坏存储本身可能无法保存它自己的故障标记，未来宿主必须检查最终状态并标为不完整。
超时或异常前已部分写入的数据属于“未确认”，不能当作确定丢失后无条件重放。
第三方 writer 必须真正异步并遵守取消；不能安全强杀同步卡死的外部 I/O。
当前接口不承诺交易所逐笔完整性，也不恢复或回补实时 Flow 基线。

## 同时修复的输入边界

原 RTVolume 时间解析在时间戳非法或溢出时可能保留 DateTime.UtcNow，
将坏时间当成当前有效成交。现改为拒绝该输入；记录旁路启用时只留下安全的无效样本质量标记。
有效推送、累计差值算法、设置默认值和调度不变。

记录元数据使用实际收到回调的请求 ID，而非可能已被新订阅替换的可变 ID。
RegularTrades 与 AllTimeAndSales 的重置／乱序检测分别维护；仅用于历史质量元数据，
不会回写实时聚合器或把未观察区间补成成交。

## 新增七组离线验证

1. 默认禁用不分配事件、不可变节点副本、禁用查询、取消、参数验证及普通版隔离。
2. 慢 writer 下有界队列，10,000 次并发拥塞尝试及时返回；排空、无新行情缺口写入和停机最后账本。
3. writer 故障停止、不重试、在途与排队损失统计，以及限时／并发释放。
4. 两个 IB 消费者共享一次源捕获；OI 零、未知源时间、两种成交口径、重置、乱序、非法时间与代际。
5. 八个 Nightwatch 等待者和缓存只捕获一次；两个数据集独立，采样时间、节点所有权和捕获错误隔离。
6. 订阅替换／结束、旧回调忽略、新观察开始；writer 故障不停止实时扇出。
7. 历史查询半开区间、合约过滤、分页／取消、每插件记录所有权冲突及旧释放句柄不影响新记录段。

这些使用假 Socket、内存 reader／writer 和可取消慢存储，不消耗行情线或 API 配额。
完整 92 组同时保留前五批的兼容、复用隔离、布局、缓存和固定／Rolling 回归。

## 最终发布基准

沿用第五批 actual_publish 测试：.NET 10.0.5、Windows 10.0.26200、seed 2210，

48 组覆盖 Fixed／Rolling、1／3／5／10 分钟、42／84 合约、1／2／8 消费者。

### 原计划尚未完全落地的优化

以下明确列为剩余工程项，不因批次编号已到第六批而视作完成：

- IB 业务接收仍是同步扇出，尚未改成有界接收／聚合队列；PERF 接收队列和行情缺口仍为 N/A。
  本批存储旁路队列不能替代业务接收队列。
- Fixed 仍保留两小时累计样本，已优化查找和完成桶缓存，但尚未完全改成增量、仅保留必要桶状态的方案。
- 已有数据／格式化／布局指标缓存，但尚未完成统一重绘通知合并与完整像素几何缓存。
- IB 反射调用仍按方法扫描，尚未实现完整方法元数据缓存。

后续应结合开盘 PERF 与整日样本增长确定优先级，不在本批未经确认追加另一轮重构。
实际数据库、历史回补、历史 API pacing、订单与风险控制则是原本明确未纳入本轮的未来功能。
