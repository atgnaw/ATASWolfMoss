## 本批改变

### 后台串行发送与无锁状态读取

原来 PaceOutbound 可能在订阅锁内 Thread.Sleep，状态栏读取行情线数量也获取该锁。
现在状态栏读取原子计数；发送任务交给每个连接唯一的后台发送器。

- 发送采用单调时钟、滑动 1 秒窗口，仍限制为每连接最多 45 次／秒；不是增加请求频率。
- 所有 reqContractDetails、reqSecDefOptParams、reqMktData 和 cancelMktData 都通过此发送器。
- 队列最多 2048 项。调用者只入队，不在订阅锁内等待限速或 Socket 发送。
- 发送前检查失效请求；已取消的排队订阅不会在稍后重新订阅。
- 队列满或订阅／取消发送失败时标记连接故障并释放连接，避免静默遗漏取消而泄漏行情线。
- 连接初始化在后台执行。最后一个使用者退出时，通过断开连接释放服务端订阅，不再逐条限速取消后才断开。
- 45 次限制只约束本插件该连接的请求，不能代表或限制账户其他客户端。

### 共享连接与订阅生命周期

- 连接池获取、引用计数和最后释放在同一短锁内协调，避免取得正在销毁的实例。
- 同 Host／Port／Client ID 的替代连接等待旧连接释放完成；故障实例不再分配给新使用者。
- 指标旧一代调度退出后，新一代才开始；快速开关不会让多代任务同时持有订阅。
- 取消检查延伸到数据写入前，减少旧回调污染新配置的风险。
- 一张图表取消只释放自己的引用，不取消其他图表仍使用的订阅或合约发现请求。
- 相同期权链、相同执行价／到期日／Call-Put／交易类别的并发发现共享一次任务。
- 发现成功缓存复用；失败可以重试；单个等待者取消不撤销共享请求。

### ATM 换档和预算

- 原来配置新梯级时先释放整套 Flow 订阅；现在对同一个租约更新合约集合。
- 保留重叠合约及请求 ID，只取消退出范围的合约、增加新进入范围的合约。
- 先取消退出合约，再发送新增请求，避免换档瞬间额外占用预算。
- OI／RegularTrades／AllTimeAndSales 按消费者需求合并；消费者退出后移除其需求。
- 同标的多图表共用一份标的预算；QQQ 与 SPX 分配对称奇数档，保留 ATM。
- 已有合约时段信息确认不在订阅窗口的标的不占 Flow 份额，避免 QQQ 休市挤占 SPX GTH；
  首次合约发现前会保守登记需求，发现后再按实际时段调整。
- 同连接实例设置不同预算时采用较低限制，较高设置不能单方面覆盖。
- 84 条预算可容纳两个标的各 21 档；42 条预算下两个标的各分配 9 档，
  保留对称性而不强行用满余数。严重不足时实际档数可能低于设置下限 5。

预算调整不是抢占式的：已有 ATM／时间桶锁定保持原有语义，其他图表可能要等其当前
锁定期结束再缩档，新请求期间显示 LINE_LIMIT 并按原退避重试。OI 临时订阅释放也可能
带来短暂等待。同标的图表若使用不同 ATM／到期目标，合约并集仍受总预算限制，
不能保证每张图表都拿到完整请求档数。账户其他程序占用的行情线无法由插件准确统计。

### 回调和诊断

- 消费者列表只在订阅关系变化时生成不可变数组；逐次行情分发不再复制该列表。
- 保留同步行情回调及现有 Flow 数学、1／3／5／10 分钟、固定／滚动桶和 ATM 锁定规则。
- 不在本批重写样本聚合、几何缓存或增加历史数据库。
- 回归发现并修复诊断计时器略早唤醒后再次无限等待样本的问题；
  空闲期间已缓冲的诊断记录也会落盘，改用单调时钟测量刷新间隔。

PERF 的耗时／事件／发送统计口径及 CSV 字段不变。新增的发送后台循环纳入“受监测循环”，
有 IB 连接时比第一批多一个属正常，不代表多一个线程持续占用 CPU。
“行情线”仍为插件请求／保留的数量，并不是 IB 服务端确认值；“发送尝试”在真正执行发送时计数。
队列／行情缺口 N/A 仍指接收行情处理，不代表新增的发送队列不存在。

## 离线证据

Release 双 DLL：0 警告、0 错误。全套 66 项测试组通过，包含新增的：

- 91 条请求满足最多 45 次／滑动秒；有界排队、取消、失效请求和幂等释放。
- 40 个并发等待者共享发现，单个取消不影响其他等待者，失败后可重试。
- 两张相同图表仅建立 42 条订阅；释放一张不影响另一张。
- 21 档换到相邻 ATM，实际记录为 2 次取消 + 2 次新增，最高仍为 42 条。
- QQQ＋SPX 共 84 条，释放一个标的不影响另一个。
- OI／Flow 需求合并、预算不足时原子拒绝、多个预算取较低值。
- 持有订阅管理锁时，状态读取仍可完成。
- 10,000 次稳态消费者分发测得 0 字节当前线程分配；
  这只代表消费者分发层，不是整个 IB 回调或整套指标零分配。
- 50 个并发连接池使用者共享实例，引用释放、故障替代和不同 Client ID 隔离。
- 真实指标方法的 30 次快速启停，旧任务未退出时新任务不能启动；
  此测试在进入数据初始化前取消，未访问网络。
- 排队期间取消立即释放本地保留容量；取消发送失败会断开模拟连接。
- 第一批诊断、固定／滚动桶和兼容性测试全部继续通过。

IB 协调测试编译同一份生产源码并注入假 Socket，只记录请求；不代表已验证 IB 实盘回执。
自动化结果证明减少了重复请求和特定分配、移除了已知锁等待路径，
**不能据此声称 ATAS 整体 CPU／帧率改善了某个百分比**。

## 用户验收与对比

1. 将第一批备份保存在 ATAS 指标自动加载目录之外。一次只安装一个 Pro DLL；
   普通版可以同时安装，但不要把两个批次 Pro 作为两个文件同时放入自动加载目录。
2. 退出 ATAS 后替换 Pro，重新启动。参数、桶模式、时间区间、档数、图表数量保持与对照版一致。
3. 周末可验收 Summary／Record、状态面板、开关和文件输出；
   无行情时不能据此评估逐笔处理负载。无须为了离线开发开启 Gateway。
4. 开盘日登录 Read-Only Gateway 后测试同标的双图表、QQQ＋SPX、独立关闭 OI／Flow，
   留意行情线和消费者数量；最后一个 IB 使用者关闭后应回落并释放连接。
5. Record 运行至少 15 秒检查 JSON／CSV；建议性能对比采集稳定行情 10–15 分钟，
   预热相同时间，单独标注启动、换档、改设置、断线等事件。
6. 对比 Render／Publish／Callback 均值和 P95 上界、事件速率、发送／取消次数、缓存条目。
   不同开盘时段的事件量不一样，需要结合 Events/s 判断，不能仅看平均耗时。
7. 附带两版 JSON 的 build_id、CSV、截图和异常时间。
   线程数／CPU／内存可看 ATAS 进程，但它们包含其他指标，不是本插件专属开销。
