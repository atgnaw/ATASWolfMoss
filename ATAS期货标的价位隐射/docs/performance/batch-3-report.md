## 主要改动

### 聚合和数据保留

原实现每次发布前复制所有累计样本，即使固定桶随后直接返回已经发布的上一桶；
此外，每次差值计算线性扫描历史，Rolling 会创建区间样本数组。

现在：

- 在原有数据所有者锁内读取样本，直接生成独立的不可变快照，不再复制整段历史。
  渲染只读取快照，仍不获取数据锁、不等待网络。
- 用二分查找定位严格小于起点的基线和半开区间 `[start, end)` 内的首尾事件。
  无事件不补零，迟到基线、第一笔成交补计及 PARTIAL 规则不变。
- Rolling 每个连续观察区段使用可增长的环形缓冲。样本过期时前移头部，
  保留起点前最后一个基线，不再搬移整个窗口或创建 inside 数组。
- 固定模式仍保留原有两小时样本历史，但过期定位从逐项扫描改为二分查找。
  本批不缩短固定历史、不回补启动前数据、不改变重置及乱序接收策略。
- 缓冲保留受时间窗口约束，容量随实际事件数增长；没有添加会静默丢成交的硬性样本数上限。
- 交易区段、换档锁定、移出范围保留、重新进入后的观察区段分离均保留。

### 快照与重绘

- 未变化的 OI 复用快照。失效条件包含数据修订、接收时间、合约/档位集合、ATM、
  到期日、标的和请求档数，不因“同一接收时间”漏掉 OI 数值修订。
- 固定桶复用已完成帧；即使桶未变，也会更新 LIVE/CLOSED/DELAYED 状态。
- 缓存交易时段解析，交易时段字符串、时区或标的变化时重新解析。
- 原始 IB tick 不再请求一次只能画旧快照的冗余重绘。
  新快照、错误状态、设置和共享行情线数量变化仍会触发相应刷新。
  Rolling 发布周期仍为原来的一秒，不是降低数据采样或丢弃成交。

### 显示缓存

- 每个期权列缓存执行价排序、共享最大值、价格区间边界和 K/M/B 数值标签。
- 绘制和悬停命中使用同一组排序与价格边界；保留 Call 上绿、Put 下红、
  PARTIAL 标记、旧范围透明度、ATM 边框及未知值符号。
- **不缓存屏幕 Y 坐标**。每次绘制依然使用当时的比例和图表坐标变换，
  避免拖动、缩放或比例变化后出现旧位置。
- 状态文字缓存扩展到期权列和诊断模式。快照、行情线、预算、时区、图表高度、
  可见列和诊断文本变化时失效，不能把新状态或截断布局卡在旧缓存中。

代表结果（B 为字节，时间为 ms）：

| 场景 | 分配：前 → 后 | 平均耗时：前 → 后 |
|---|---:|---:|
| Fixed 5m，42 合约，1 消费者 | 5,818,074 → 224 B | 1.2566 → 0.0002 |
| Fixed 5m，84 合约，各 8 消费者 | 93,045,140 → 3,584 B | 18.2131 → 0.0024 |
| Rolling 5m，42 合约，1 消费者 | 313,888 → 45,512 B | 0.1337 → 0.0443 |
| Rolling 5m，84 合约，各 8 消费者 | 5,022,208 → 728,192 B | 1.7877 → 0.6181 |
| Rolling 10m，84 合约，各 8 消费者 | 8,892,928 → 728,192 B | 3.3219 → 0.5514 |

5m Rolling 单实例这条路径的新分配减少约 85.5%。
Fixed 的大幅下降主要来自删除“复用旧桶之前的无意义历史复制”，不是把新桶计算变成零成本。

### 解释限制

- Fixed 测量的是预热后、同一已完成桶的重复发布；224 B **不代表新桶首次构建的分配**。
- Rolling 固定测试时钟并反复计算相同窗口；真实窗口移动、数据突发和换档另有正确性回放测试，
  不能把这组耗时等同于实盘所有情况。
- 测试不包含 ATAS 的真实绘制、其他指标、网络、IB 解析和账户负载。
- 20 个样本的延迟会受调度、GC 等噪声影响；不要将微秒级差值当作稳定硬指标。
  原始 CSV 中的 P95 是排序后第 19 个值；UI 的 P95≤ 是直方图上界，两者不是同一种估算。
- 这些结果证明特定热路径的分配和重复工作减少，**不是 ATAS 总内存下降 85.5%，也不是整机 CPU/帧率改善同样比例**。
- 后续真实对比仍以你保留的 DLL、相同配置和 Record 记录为准。
