# IbOptionFlowProbe：独立 IB 期权采集验证工具

## 0.6.0：Mid 中性与报价外成交开关

- 原 U11（买卖报价相同）与 U17（中间价法中成交恰在中间价）改为 Mid，不再进入未知原因。三种分类方法原有判定顺序保持不变：逐笔涨跌法自己的 U18–U22 不自动改为 Mid。
- 报告新增“报价外成交按方向归类（U15）”，默认关闭。开启时，只有通过原报价有效性检查的报价外成交才按成交价高于 Ask 判买、低于 Bid 判卖；不是比较整笔成交权利金。不会放宽缺失、延迟、过龄等限制。
- 开关两套结果均逐笔重算，含每个时间候选、一致性、U25 分组与时间冲突；不是把汇总未知金额直接分给买卖。全部必要候选为 Mid 才归 Mid，Mid 与买卖混合为 U26，真正买卖冲突仍为 U24。
- 已分类覆盖包含 Mid，另显示不含 Mid 的买卖方向覆盖。倾向仍为 `(买−卖)/(买+卖)`；总量包含 Mid，未知边界中的 Mid 按零净方向处理。这是假设性中性分类，不是中性真值，边界仍不包含分类错误。
- JSON 的 `robustness` 为默认结果，`outside_quote_robustness` 为开启结果；逐笔文件相应保留 `direction_evidence` 与 `outside_quote_evidence`。旧对账统计作为原始基线保持不变，原始采集与旧报告不修改。

0.5.3 修复：离线分析不再保留 12 合约旧上限，支持当前采集器最大 164 个合约，仍拒绝重复或无效合约 ID。0.5.2 已成功采集但提示“合约清单无效”的运行无需重采，使用新版 `analyze <原采集目录>` 即可。采集后报告失败单独返回退出码 3（采集完整）或 4（采集不完整），启动脚本不再把所有错误笼统显示为采集失败。

### 新报告的阅读顺序

1. 默认查看 1 分钟、常规成交、中间价法＋多候选一致；按品种、执行价、Call/Put、时间桶筛选，每页 50 行。
2. 同时查看倾向、分类覆盖、未知边界及质量标记。未知边界跨零表示未知成交本身即可推翻正负结论。
3. 抗误判余量 `max(0, |B-S|-U)/(2T)` 是条件性压力测试，不是正确概率。详情含 1%/2%/5% 压力、单笔及前五笔权利金集中度。
4. 方法下拉可比较三种分类算法。7 组年龄阈值 × 3 方法，加 5 组源时间偏移 × 3 方法，共 36 个基础场景，另有 3 个一致性汇总。详情显示当前方法的 12 个基础场景，切换方法可以比较其余场景；完整数据均可下载。

历史报价按接收单调时间保存 60 秒及窗口前检查点，每合约上限 65,536 状态；源时间偏移为 -250/-100/0/+100/+250 ms。目标时刻在成交接收之后的候选不可用，不夹到接收时刻，也不回看后到报价。这些偏移是假设，不是测得的网络延迟；Bid/Ask 缺少交易所时间戳，不能证明真实主动方向。

主结果使用无年龄上限 Midpoint：最新报价有效、至少两个时间可行源候选，并且全部时间可行候选都有有效方向且一致，才归入 Buy/Sell，否则进入未知。同一报价被多次引用不代表独立证据。MidpointTick 仅为扩展对照，正中间价才用同合约/口径最近 5 秒内 tick 方向，不跨断线、重置、区段、歧义或倒序事件继承。

不足 30 个事件、首尾部分桶、本地不完整、非实时、观察中断或时钟跳变会阻止正式方向判断。跨桶累计差无法精确分摊单列 `RECONCILIATION_BOUNDARY`，并不等于本地丢失。累计对账差、VWAP 差及缺少比较基线均单列，所有结论只针对已观察明细，不为未观察部分虚构方向或权利金。

`report.json` 保留原七组分析，同时增加 `robustness`。`decisions-*.jsonl` 的 `direction_evidence` 保留候选目标时刻、Bid/Ask 引用序号、年龄、拒绝原因和 36 组分类，可追溯原始事件；233/375、Call/Put、品种及交易区段分别统计。

已实现独立原始采集、后台 JSONL 记录、固定合约范围、资源释放、离线完整性检查、报价匹配、分口径对账、1/3/5/10 分钟分析及 HTML/JSON 报告。
`analyze`、`demo`、`inspect`、`check-runtime` 和 `benchmark` 均不连接网络。只有显式 `capture --live` 会连接 Gateway，采集结束后自动生成分析报告。
真实账号的接口可用性、数据覆盖率和估计稳定性需第三批显式实测；离线测试通过不代表真实数据一定适用。

## 真实采集（第三批再执行）

1. 登录 Gateway，启用 Socket API，建议使用 Read-Only API。
2. 关闭 ATAS 的 IB 数据列或退出 ATAS，按启动时显示的需求预留行情线（默认两个品种共 12 条）。独立 Client ID 不增加账户行情额度。
3. 确认 Client ID 2290 没有被使用，也没有被配置为 Master ID；需要时改成其他非零 ID。
4. 在发布目录双击 `Start-Probe.cmd`，输入品种和各自参考现价。无需双击 EXE；也可右键 `Start-Probe.ps1` 使用 PowerShell 运行。
5. 检查连接参数和占用数量，输入 `START` 才会连接。

默认 QQQ、SPX 各 3 个执行价 × Call/Put，共 12 个合约，采集 30 分钟。可只采一个品种。

0.5.2 新增启动问题“ATM 上下各多少档执行价”，范围 0–20，默认 1。N 表示 ATM 本档 + 下方 N 档 + 上方 N 档，按实际可用执行价档位选择，不是价格点数；每档均采 Call 和 Put。0 表示仅 ATM；3 表示每品种 7 档 / 14 条行情线，QQQ+SPX 合计 28 条。所有选中品种使用同一个 N。JSON 配置对应 `"strikes_each_side": 3`，旧配置省略时仍为 1。

行情线需求为 `品种数 × (2N+1) × 2`，不再固定限制为 12；这只是程序需求，不代表 IB 账户一定有该额度，超限仍会停止。整轮合约固定、不随行情换档。完整对称范围不足或在 128 个候选的发现保护上限内无法验证时明确失败，不缩小范围、不改到期日；更大范围也可能触发准备超时或更快达到文件容量上限。
参考现价来自用户输入，不订阅标的价格；程序验证到期日实际存在的双边合约后锁定 ATM±1 档，整个运行不换档。
QQQ 仅 RTH；SPX 按 IB 返回的实际合约开放时段允许 GTH/RTH，前晚 GTH 使用下一交易日到期合约。闭市、缺少合约或无法确认时段会退出，不在后台等待开盘。
跨出当前合约开放区段时结束本次运行，不把维护间隔两侧连接成一段连续观测。

也可手动编辑 `probe.example.json`（示例现价为 0，必须填写有效现价；不提供可能被误用的过期价格），然后运行：

```powershell
./IbOptionFlowProbe.exe capture --live --config ./my-config.json
```

`--live` 是必需参数。Ctrl+C 会停止采集、取消订阅、断开本程序连接并保存摘要。
启动脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5.1。参数错误或取消后会暂停显示提示；CMD 入口还会保留脚本加载失败的提示。其 RemoteSigned 策略只用于当前子进程，不修改系统或用户的持久设置，域策略仍然有效。
Client ID 冲突不会自动换号；断线不会自动重连；需要继续时重新启动一个独立运行。

## 文件与含义

默认位置：`%LOCALAPPDATA%/WolfMoss/IbOptionFlowProbe/runs/<UTC时间>-<唯一编号>`。
每次运行创建新目录，不覆盖旧记录。只有用户主动指定输出目录时才改变位置；不要把真实行情数据放入代码仓库。

- `manifest.json`：格式版本、程序版本、运行编号、配置、单调计时频率。最初的合约列表为空，正式清单见下一个文件。
- `contracts.json`：验证后的 con_id、到期日、乘数、固定 ATM、IB 原始时段和本次开放区段。发现失败时可能不存在。
- `capture-start.json`：订阅准备完成时间；之前可能已经接收到部分合约的回调，不能把准备完成前的区间当作全量覆盖。
- `events-00001.jsonl` 等：原始回调、接收 UTC、单调时钟、顺序号、合约身份、RT 字段解析结果。
- `capture-summary.json`：结束原因、本地完整性、写入数量、队列峰值、丢弃数、写入失败和观察接口失败次数。
- `analysis-<时间>-<编号>/report.html`：浏览器可直接打开的本地中文报告；每次分析使用新目录，不覆盖原始数据。
- `analysis-.../report.json`：全部合约、口径、时段、四种桶长度和四组阈值的完整汇总。
- `analysis-.../decisions-*.jsonl`：每个成交回调的处理原因、两侧报价/数量原始序号、年龄、源时间差和四组分类结果。

`complete` **仅表示本地运行按时结束且没有已知记录丢失**，不代表 IB 提供了全部成交，也不代表方向判断准确。
延迟/冻结行情通过 `marketDataType` 记录；后续分析必须按这些状态区分，不能当作实时数据。
233 和 375 分别保留字段 48、77；不会在采集时求和、去重、纠正时间或分类方向。
Bid/Ask、报价数量的独立更新由回调类型、field、value 和各自到达时间保存；没有伪造交易所报价时间。
IB 错误只保存代码和请求编号，不保存错误全文、账户标识或高级拒单 JSON。

队列默认 65,536 条。原始文件 128 MiB 分卷，总量 2 GiB 后停止。容量不足、磁盘失败或回调记录异常都不能产生“完整无损”结论。
控制台每秒显示事件速率、队列峰值、丢弃、写入量、CPU 和内存；不逐条打印行情。
运行文件由用户自行保留、归档或删除；程序不会自动清理历史运行。

## 离线检查

```powershell
./IbOptionFlowProbe.exe check-runtime
./IbOptionFlowProbe.exe inspect 'C:/path/to/run'
```

两个命令都不连接 Gateway。`check-runtime` 只验证嵌入 API 能被加载。`inspect` 按流读取原始文件，报告有效记录数、解析问题、文件损坏和异常结束。
尾部残缺 JSON 可以跳过并标记；中间损坏不能被静默视为正常记录。
退出码：0=命令正常完成；1=参数/文件操作失败；2=capture/inspect 的不完整运行。`analyze` 成功生成报告不等于数据适合判断方向，必须查看报告结论。

## 离线分析和模拟演示

```powershell
./IbOptionFlowProbe.exe analyze 'C:/path/to/run'
./IbOptionFlowProbe.exe demo 'C:/path/to/demo-output'
```

分析保留相同输入产生相同 report.json 的可重复性，不把分析执行时间写入统计结果。演示数据及报告醒目标记 SYNTHETIC，不能当作实盘验证。

- 同一合约的 233 与 375 分开，Call/Put 分开。首次累计样本只作基线。
- 完全重复载荷、倒序、无法确认的修订不强行认作新成交；成交时间/价格/数量完全相同但累计量改变时标为 AMBIGUOUS_SAME_PRINT，而不是假设发生了第二笔相同成交。断线、记录缺口、累计重置或区段变化建立新基线。
- 匹配只用成交回调到达之前的报价。Bid/Ask 分别使用单调时钟测量价格年龄，数量更新不会刷新价格年龄。
- 四组阈值为 100/250/500/1000 ms；报价源未确认为实时、缺失、锁盘、交叉、无效或过龄均为 UNKNOWN。
- 成交价精确等于 Ask/Bid 才分别归类 AT_ASK/AT_BID；价差内部和报价外另列，不推测主动方向。
- 每笔原始源时间保留；毫秒级超前不被偷偷纠正。接收顺序估计不等于交易所成交时刻的 BBO。
- `ObservedVolume` 仅是可识别成交明细之和；`ComparableObservedVolume` 只包含与累计增量处于相同比较对的部分。
- 桶边界没有精确采样时，不分摊跨桶累计变化；`BoundaryCrossings` 单独计数，桶标为 PARTIAL。无回调桶显示 NO EVENTS / 未知，不补成真实零成交。
- 权利金使用合约乘数；累计 VWAP 修订和精度可能造成差额。对账覆盖率可超过 100%，不截断，不按最后一笔方向分类缺失量。
- 小于 30 个可识别事件为内部样本提示，不是官方准确率标准。报告永不宣告真实主动方向准确率已验证。

分析逐笔证据按 128 MiB 分卷、上限 2 GiB，达到上限会失败并保留不完整输出，不生成伪装成功的汇总。HTML 每种桶长度最多预览 500 行，JSON 保留完整统计。原始数据不变；默认分析最多 30,000 个统计行。
